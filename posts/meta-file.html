_meta 文件是 Nextra 用来配置站点结构和导航的文件，它决定了页面标题、排序、哪些页面出现在导航栏、哪些被隐藏等行为。

文件长什么样

_meta 文件支持 .js / .jsx / .tsx 后缀，导出的是一个普通的对象：

key 是文件（或文件夹）的名字，对应实际的路由；value 是显示在导航里的标题。最简单的写法就是 key: '标题'。

没在 _meta 里列出的页面会追加到末尾并按字母排序（index 例外，它永远排最前）。

_meta 和 _meta.global 的区别

Nextra 4 新增了 .global 后缀的变体：只用单个文件配置整个站点。

  • _meta.js：每个文件夹一个，放在对应目录下
  • _meta.global.js：全局单文件，但文件夹条目必须带 items 字段

注意：_meta.global 和 _meta 不能同时使用，只能选一种。

两个容易踩的坑

  1. key 不要用数字。JavaScript 对象里数字键永远排在前面，1992_10_21 会被自动转成 '19921021' 并排到最前。想要按日期排序，应该用字符串加前缀，比如 '10-21-post'。
  2. _meta.global 里的文件夹必须有 items，这是它和普通 _meta 唯一的语法差异，漏了会报错。

小结

  • 字符串简写：key: '标题'
  • 对象展开：type / display / title / theme
  • type: 'page' 进导航栏，display: 'hidden' 藏起来但保留 URL
  • 文件夹（.global 场景）用 items 配置子条目
  • '*' 键给同目录所有条目做兜底

配置起来之后，新增一篇文章只需要建 app/posts/<slug>/page.mdx，导航、列表、RSS 都会自动跟上。
