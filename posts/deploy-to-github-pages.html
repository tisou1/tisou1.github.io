这篇记录的是本站上线的全过程。博客本体跑通之后，“部署到哪、怎么自动发布”就成了下一个问题，这一趟下来踩的坑不少，最典型的是一个叫 .nojekyll 的空文件。

方案选型：三种部署路径

GitHub Pages 有两种站点类型，部署方案要围绕它们来选：

类型仓库要求访问地址
User site仓库必须叫 <用户名>.github.iohttps://tisou1.github.io
Project site任意仓库https://tisou1.github.io/<仓库名>

由此延伸出三种常见路径：

  1. 子路径部署：nextra-blog 仓库直接开 Pages，访问 .../nextra-blog/。最简单，但要在 next.config.ts 配置 basePath，所有静态资源都会带一层前缀
  2. 重命名仓库：把仓库改名为 tisou1.github.io，源码零改动，但仓库名被固定
  3. 双仓库模式：保留 nextra-blog 存源码，另建一个 tisou1.github.io 空仓库存构建产物，用 GitHub Actions 桥接

我选了第 3 种：日常只更新 nextra-blog，推送后 Actions 自动构建，把静态产物推到 tisou1.github.io，站点根域名访问。

双仓库架构

发布仓库只放构建产物，历史只有一条最新部署的提交（每次 force push 单条全新 commit），干净且可回溯。

前置配置（网页端，一次性）

  1. 创建空仓库 tisou1.github.io，不要初始化 README
  2. 生成 Fine-grained PAT（GitHub → Settings → Developer settings），权限只需两项：仓库范围选 tisou1.github.io，权限只给 Contents: Read and write
  3. 把 token 存到 nextra-blog 仓库的 Actions Secret，名称 DEPLOY_TOKEN

为什么需要 PAT？因为 workflow 里默认的 GITHUB_TOKEN 只有当前仓库的写权限，推不到另一个仓库。

最大的坑：.nojekyll

现象：第一次部署后，https://tisou1.github.io 首页能打开，但 CSS、JS 全部 404，页面裸奔。

原因：GitHub Pages 在「Deploy from a branch」模式下，收到文件后默认先用 Jekyll（Ruby 静态站生成器）处理一遍再发布。而 Jekyll 有个约定：所有下划线开头的目录都被视为内部目录，构建时不发布。

Next.js 的产物恰恰全是下划线开头：

HTML 不带下划线所以能打开，但页面引用的 /_next/static/... 在服务器上根本不存在，404。

解法：在产物根目录放一个空的 .nojekyll 文件。它是 GitHub Pages 约定的开关标记——检测到它就跳过 Jekyll，你推什么就发什么。官方文档在《Configuring a publishing source for your GitHub Pages site》的 troubleshooting 章节提到：外部 CI 部署时”typically include a .nojekyll file”，Pages 会因此识别出该分支”不需要构建步骤”。

验证：修复后用脚本检查所有资源状态码，CSS/JS 从全 404 变成全 200。

这一步对所有非 Jekyll 项目（Next.js、Vue、Sphinx 等）都是必做的——只要产物里有 _ 开头的文件或目录。

第二个坑：PowerShell 中文提交乱码

在 Windows PowerShell 里直接 git commit -m "中文信息"，提交信息会变成类似 鏀圭敤璺ㄤ粨搴撴帹閫侀儴缃插埌 的乱码——shell 向 git 传参时发生了 GBK/UTF-8 编码混淆。

解法：中文提交信息不走命令行，写进 UTF-8 编码的文件再用 -F 提交：

如果乱码 commit 已经推上去了，只能重写历史修复：git reset --soft <目标提交> 后重新提交，再 git push --force-with-lease 覆盖。--force-with-lease 比裸 --force 安全——如果远端有别人的新提交会拒绝推送。

验证清单

部署完成后我逐项核验过，供以后排查时参考：

  • 首页 https://tisou1.github.io/ → 200
  • CSS / JS（/_next/static/...）→ 200（.nojekyll 生效的标志）
  • RSS https://tisou1.github.io/rss.xml → 200
  • 搜索索引 /_pagefind/pagefind.js → 200
  • 文章页（如 /posts/hello-nextra）→ 正常渲染

一个细节：Next.js 静态导出生成的是 hello-nextra.html 而不是 hello-nextra/index.html（因为默认 trailingSlash: false），所以直接访问 /posts/hello-nextra/（带尾斜杠）会 404，但站内链接都是无斜杠形式，GitHub Pages 会自动 301 到 .html，不影响正常浏览。

日常更新流程

配置完成后，写博客的流程就是：

  1. 在 app/posts/<文章名>/page.mdx 写新文章
  2. 提交并推送到 nextra-blog
  3. Actions 自动构建推送，约 1~2 分钟后站点更新

完全不用碰发布仓库。唯一要记得的是 PAT 有有效期，到期后重新生成并更新 DEPLOY_TOKEN secret 即可。
